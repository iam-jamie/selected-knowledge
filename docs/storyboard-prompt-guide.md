# YouTube 分鏡設計師

這個 skill 記錄一套完整、已經跟使用者反覆測試過的分鏡製作方法論。使用者的完整生產流程是：

```
SRT逐字稿 --(這個skill)--> storyboard.json --> prompts.txt --> ViralDNA/Google Flow 產圖
                                 │
                                 ├─> corrected.srt（校正後字幕，給剪輯用）
                                 └─> fetch_sfx.py 抓音效 --> sfx_map.json --> build_video.py 合成影片
```

你的任務**只有**「SRT + 風格指南 → storyboard.json」這一段。後面的圖片生成、影片合成，使用者已經有現成的 Python 腳本（在 `scripts/` 資料夾裡：`split_prompts.py`、`fetch_sfx.py`、`build_video.py`、`json_to_srt.py`），你不用重寫，除非使用者要求修改。

---

## 輸入

1. 一份 SRT 逐字稿（可能是簡體中文，可能有語音辨識錯字）
2. 一份視覺風格指南（描述美術風格、色票、構圖規則、角色設計等）
3. 繁體中文的腳本（用來修正 SRT file）

如果使用者只給了其中一個，先跟他要另一個，兩個都需要才能開始。

---

## 輸出：storyboard.json

一個 JSON 陣列，每個元素是一個分鏡，欄位如下：

```json
{
  "scene_id": 1,
  "start": 0.16,
  "end": 5.92,
  "duration": 5.76,
  "text": "繁體中文，分鏡合併後的版本（給你自己設計image_prompt時參考畫面內容用，不是字幕）",
  "image_prompt": "英文，套用風格指南",
  "sfx_keyword": "small bell ding",   // 可省略（無音效時整個key不用寫或設null）
  "sfx_type": "rhythm",                // 只有節奏音效才需要這個欄位
  "sfx_offset": 2.9,                   // 可省略，音效在分鏡內第幾秒響起
  "cues": [                            // 原始SRT逐句時間戳+校正後文字，不合併，給字幕輸出用
    {"start": 0.16, "end": 1.64, "text": "那是一萬五千年前"},
    {"start": 1.64, "end": 5.92, "text": "你是一位生活在歐亞大陸某處的狩獵採集者"}
  ]
}
```

**注意 `text` 跟 `cues` 是兩個不同用途的欄位，不要搞混：**
- `text`：分鏡合併後的版本，只給你自己判斷「這個分鏡該畫什麼」用，**不會**被拿去當字幕
- `cues`：保留原始 SRT 每一句的時間戳，只做逐句校正、不合併，這才是**實際會被轉成字幕檔**的內容（`json_to_srt.py` 讀的是 `cues`，不是 `text`）

## 步驟一：分鏡切分邏輯

### 前 60 秒: 預設照原始字幕的節奏走
- 一句字幕對應一個分鏡

### 後 60 秒：每個分鏡持續 4 - 7 秒
- 不要一句字幕對應一個分鏡，而是把多個單句接在一起，畫出最適合這幾句的畫面

### 確保分鏡跟原始的 SRT 時間戳對的上
1. 分鏡的 `start`/`end` 必須是原始 SRT 時間戳的**精確延續**（用第一句的 start、最後一句的 end），不能自己捏造時間。
2. **完成後務必檢查（硬性規定，不是「大概對得起來」就好）**：所有分鏡 `duration` 加總必須**精確等於**原始逐字稿總時長（最後一句字幕的 `end`），容許誤差 < 0.1 秒。
   - 若對不上，先檢查是不是切分時漏掉或重複算到某一段。
   - 也要檢查是不是句子跟句子之間的**停頓空隙**沒有算進任何一個分鏡——下游 `build_video.py` 用 concat 疊圖時只認每個分鏡的 `duration` 依序往下疊，完全不看 `start`/`end` 的絕對時間，所以只要有空隙沒被算進去，畫面就會從那一刻開始跟旁白錯位，而且會一路累積到片尾，不是只有片尾少幾秒而已。
   - 修法：把每個分鏡的 `end` 延長到**下一個分鏡的 `start`**為止，吃掉中間的停頓間隙，`duration = end - start` 照這個重新算；第一個分鏡的 `start` 直接設為 0（蓋掉旁白開口前的靜音）；最後一個分鏡維持原始最後一句字幕的 `end` 不變。
   - 這個延展**只動 `start`/`end`/`duration`**，`cues`（逐句字幕時間戳）維持原始 ASR 時間戳不變，因為 `json_to_srt.py` 讀的是 `cues`，字幕時間必須跟原始 SRT 一致。

---

## 步驟二：繁體中文文字校正（分兩層，不要搞混）
- 核心原則：分鏡怎麼分（給圖片用）跟字幕怎麼切（給觀眾看）是兩件事，不要用同一個時間顆粒度。
- 使用者會提供繁體中文的腳本，可以依照那份腳本去校正 SRT file。如果沒給記得詢問使用者
### (A) `cues`：逐句校正，絕對不合併
1. 每個分鏡底下的 `cues`，是**原始 SRT 逐句**的時間戳（一句不合併、不拆分，跟原始 SRT 的句子邊界完全一樣）
2. 對每一句分別做：
   - 簡體轉繁體
   - **修正明顯的語音辨識（ASR）錯字**，依上下文判斷合理的字。例如：
     - 「入圣」→「入勝」（引人入勝）
     - 「律食者」→「捕食者」
     - 「长毛」（前後文是「你沒有把長毛扔向牠」，講的是丟東西攻擊動物）→「長矛」（合理推斷是同音錯字）
3. **不確定的錯字不要亂猜**，專有名詞不要亂改。維持原字或跟使用者確認——這是最終會被 `json_to_srt.py` 直接轉成字幕檔的文字，校正要謹慎
4. 一個分鏡底下可能有 1 句、也可能有 3-4 句 `cues`（取決於這個分鏡合併了幾句原始字幕），把落在該分鏡時間範圍內的原始句子都放進去，不要漏掉或跨分鏡放錯

### (B) `text`：分鏡合併版，只給你自己參考用
1. 把該分鏡涵蓋的所有 `cues` 文字合併成一句，用逗號自然銜接，語意通順即可
2. 這個欄位**只是給你自己判斷「這個分鏡的畫面該畫什麼」用**，不會被輸出成字幕，所以合併方式不用太講究
3. 不要把這個欄位跟 `cues` 弄反——曾經犯過的錯誤是把 `json_to_srt.py` 設計成讀 `text` 輸出字幕，結果字幕變成 3-5 秒一大句、擠在一起很難讀，後來改成讀 `cues` 才修正

## 步驟三：image_prompt 撰寫規則

1. **用英文寫**，圖生模型效果比中文好。
2. **每一行 prompt 都要重複寫一次完整的風格描述**（美術風格、線條質感、配色系統、構圖規則）。不能只在第一行寫、後面省略——因為下游工具（ViralDNA）是逐行獨立丟給 Google Flow 生圖，沒有上下文延續，每一行必須是自己完整、獨立的 prompt。
3. 從使用者提供的風格指南裡**抽取一個固定的風格描述句尾**（style suffix），原封不動貼在每個 prompt 後面，確保分鏡風格統一。
4. 依照風格指南的色票，**依畫面情緒/場景類型挑對應色調**
5. **抽象敘述句**（沒有具體畫面可畫的句子，例如「這意味著…」「事情沒那麼簡單」）**用符號化/圖表化手法**表現，不要硬掰一個寫實場景。常用符號：紅色✕、綠色勾、問號、燈泡、時間軸、箭頭、裂開的愛心、天平等。
6. Prompt 長度抓 30-50 字英文為佳，太長可能被生圖工具截斷或稀釋效果，先問使用者的下游工具有沒有字數限制。

---

## 步驟四：音效設計（sfx_keyword / sfx_type / sfx_offset）

音效分成**兩種來源**，欄位標法不同：

> **總規則（最重要）：** 凡是出現在下方「固定詞庫表」裡的詞（包含 `mouse click`），一律標 `"sfx_type": "rhythm"`，不論是畫面轉換還是敘事節奏。這些音效存在使用者本地資料夾，**不會**去音效庫搜尋。**沒有標 `rhythm` 的音效，下游 `fetch_sfx.py` 會拿去 freesound 搜尋。**

#### (A) ：內容音效（畫面配對，預設類型）
- 只在真的有加分的分鏡才標，不用每個分鏡都配
- 前 60 秒的 mouse click，只留在段落切換和重點畫面，不是每鏡都放。
- 節奏音效只留給真正的重點：專有名詞第一次出現、揭示、反轉、列舉。
- 內容音效只留給畫面裡真的會發出聲音的東西（狗叫、鬧鐘、翻頁）。
- 如果想用 `mouse click`，它屬於固定詞庫，**不算內容音效**，請改照下方 (B) 的規則標 `"sfx_type": "rhythm"`，不要放在這一類
- `sfx_keyword` 用 **2-3 個字的通用英文詞**，模仿音效庫的標籤習慣，不要寫長敘述句
  - ✅ `crackling campfire`、`wolf growl`、`dog bark`、`leaves rustling`
  - ❌ `the sound of bushes rustling softly in the night wind`（太長太具體，音效庫搜不到）
- 不用加 `sfx_type`（預設就是內容音效，會去音效庫搜尋）。**只有「不在固定詞庫表裡」的詞才能這樣用**
- `sfx_offset` 通常不用設（預設 0，分鏡一開始就響）

#### (B) 節奏音效（敘事節奏用，強調/疑問/反轉/幽默/ 專有名次/ 揭示訊息/ 揭露真相）
- 用來標記「這句話的語氣需要一個節奏音效」，不是配畫面，是配**敘事節奏**
- `sfx_keyword` **只能用使用者預先準備好的固定詞庫**（見下方清單），不能自己發明新詞，因為這些音效是使用者手動挑選、存在本地資料夾裡的固定檔案，不是去音效庫現搜
- 必須加 `"sfx_type": "rhythm"`（`mouse click` 也一樣，即使它只是用來標畫面轉換）
- `sfx_offset` 通常設在**接近分鏡結尾**（例如 `duration - 0.4`），讓音效卡在句子講完的瞬間，不要在句子講一半就響
- 講到重點或者專有名詞的時候一定要搭配音效固定詞庫！！
- 如果要”揭示“ 什麼事情的時候一定要使用音效固定詞庫！ 
- 有 “列舉” 一定要使用音效固定詞庫

**目前的節奏音效固定詞庫（只能用這些，不能自創）：**

| 分類 | 關鍵字 | 適用情境 |
|---|---|---|
| 強調重點 | `pop bright` | 講到關鍵數字/結論/"重點來了" |
| 強調重點 | `whoosh` | 轉場、切換到下一個論點 |
| 強調重點 | `impact hit` | 戲劇性、嚴肅的句尾 |
| 疑問句 | `small bell ding` | 疑問句句尾，製造懸念 |
| 疑問句 | `curious rise` | 音調上揚，貼合問句語氣 |
| 疑問句 | `question rise` | 同上，備用選項 |
| 反轉/打臉 | `record scratch` | "事情根本不是這樣"這種反轉句 |
| 反轉/打臉 | `wrong buzzer` | 破除常見迷思、糾正錯誤觀念 |
| 反轉/打臉 | `correct ding` | "沒錯，就是這樣"的肯定句 |
| 列舉 | `ui click` | 條列式內容逐項出現（"第一、第二、第三"） |
| 幽默/諷刺 | `cartoon boing` | 誇張、自嘲、反諷語氣 |
| 段落標題 | `keyboard` | 打字機音效，表示這是段落標題 |
| 畫面轉換 | `mouse click` | 畫面轉換萬用音效 |
| 揭示訊息/ 揭露真相 | `magic` | 揭示訊息/ 揭露真相 |

## 完成後的檢查清單

在把 storyboard.json 交給使用者之前，自己過一遍：

- [ ] 所有分鏡 `duration` 加總精確等於原始逐字稿總時長（誤差 < 0.1 秒），句子間的停頓空隙已經吃進前一個分鏡的 `end`，不是被跳過
- [ ] 分鏡預設是原始字幕 1:1，只有短接續詞併句、列舉句合併這兩種例外，沒有為了湊時長而強行合併
- [ ] 每個分鏡的 `cues` 涵蓋該分鏡時間範圍內**所有**原始 SRT 句子，時間戳跟原始 SRT 一致、沒有漏句或跨分鏡放錯
- [ ] `cues` 裡的每句都是繁體中文，明顯錯字已修正，且**沒有合併**（維持原始逐句）
- [ ] `text`（分鏡合併版）只用來輔助設計畫面，沒有跟 `cues` 搞混
- [ ] 所有 `image_prompt` 都用英文，且每行都包含完整風格描述
- [ ] 角色設計全片一致，沒有中途冒出新角色
- [ ] 音效欄位：內容音效用通用詞、節奏音效只用固定詞庫並標 `sfx_type: "rhythm"`
- [ ] 逐一檢查：所有 `sfx_keyword` 只要在固定詞庫表裡（含 `mouse click`），都已標 `sfx_type: "rhythm"`；沒標 `rhythm` 的詞確認不在詞庫表內
- [ ] 不要自己先做重排、直接輸出，讓使用者看過分鏡設計後再決定要不要跑後續腳本

直接產生 `storyboard.json` 檔案（用 create_file 工具寫檔案，不要只在對話裡貼 JSON 文字），交給使用者。
